**PROJETO DAS DISCIPLINAS \- PROGRAMAÇÃO DE DISPOSITIVOS MÓVEIS E PROJETO EXTENSIONISTA IV \- 2026.2**

**1\. OBJETIVO GERAL**  
Desenvolver, em grupo, um aplicativo mobile utilizando React Native, que resolva uma problemática real da comunidade, atendendo aos princípios do Projeto Extensionista IV.

O projeto deverá unir:

* Aplicação prática dos conteúdos técnicos da disciplina;  
* Desenvolvimento de solução digital funcional;  
* Impacto social real;  
* Validação com comunidade ou organização.

**2\. ORGANIZAÇÃO DOS GRUPOS**

* Grupos de até 5 integrantes;  
* Cada grupo desenvolverá um projeto diferente.

**3\. REQUISITOS OBRIGATÓRIOS DO PROJETO**  
Para que o projeto seja aceito e avaliado, deverá conter obrigatoriamente:

**3.1. Requisitos Extensionistas (Projeto Extensionista)**  
O projeto deve:

1. Resolver uma problemática real: O problema deve existir de fato e afetar pessoas ou organizações reais;  
2. Estar alinhado ao impacto social: A solução deve gerar melhoria concreta na realidade do público-alvo;  
3. Dialogar com comunidade ou organização: Deve haver validação real por meio de:  
   1. Entrevista;  
   2. Formulário;  
   3. Visita;  
   4. Conversa formal registrada;  
   5. Evidências deverão ser anexadas.  
4. Gerar plano de intervenção: O grupo deve explicar:  
   1. Como a solução será aplicada  
   2. Como será apresentada  
   3. Como será testada  
   4. Como será medido o impacto

**3.2. Requisitos Técnicos (React Native)**  
O aplicativo deverá obrigatoriamente conter:

1. Estrutura com múltiplas telas: Uso de navegação (Stack ou equivalente), contendo ao menos 4 telas.  
2. Uso de componentes básicos:  
   1. View;  
   2. Text;  
   3. Image;  
   4. ScrollView;  
   5. Pressable.  
3. Organização em componentes: Separação adequada de responsabilidades e criação de componentes reutilizáveis.  
4. Uso de Props: Comunicação entre componentes.  
5. Layout organizado e moderno: Boa organização visual (não precisa ser complexo, mas deve ser bem estruturado).  
6. Dados dinâmicos:  
   1. Estado local;  
   2. Consumo de API (API PRÓPRIA).  
7. Tratamentos de loading e erro.

**4\. ENTREGAS OBRIGATÓRIAS**  
O projeto será dividido em etapas.

**4.1. 1ª Entrega – Proposta do Projeto \- 03/09/2026 \- %**  
Documento contendo:

1. Descrição do problema;  
2. Público-alvo;  
3. Proposta da solução;  
4. Funcionalidades previstas;  
5. Protótipo ou esboço das telas;  
6. Cronograma.

Sem essa aprovação, o grupo não poderá continuar o desenvolvimento.

**4.2. 2ª Entrega – Diagnóstico da Problemática e Plano de Intervenção \- 24/09/2026**  
Documento contendo:

1. Diagnóstico Detalhado da Problemática;  
2. Análise do Público-Alvo;  
3. Plano de Intervenção;   
4. Ajustes na Proposta Inicial.

**4.3. 3ª Entrega – Versão Beta Funcional \- 28/10/2026**  
Deverá ser entregue o app, contendo todos os pontos do item 3.2. Requisitos Técnicos (React Native).

**4.4. 4ª Entrega – Entrega Final \- 25/11/2026**  
Deverá conter:

1. Demonstração do aplicativo funcionando;  
2. Explicação do problema;  
3. Como foi validado;  
4. Como a solução resolve a problemática;  
5. Evidências de aplicação/teste;  
6. Reflexão final do grupo.

**5\. CRITÉRIOS DE AVALIAÇÃO**  
A nota será composta pelos seguintes critérios:

**5.1. Clareza do Problema**

* Problema é real?  
* Está bem descrito?  
* É relevante?

**5.2. Validação com a Comunidade**

* Houve diálogo real?  
* Existem evidências?  
* A solução foi pensada com base nessa validação?

**5.3. Coerência da Solução**

* A solução realmente resolve o problema?  
* Existe lógica entre problema e aplicativo?

**5.4. Qualidade Técnica**

* Estrutura correta;  
* Navegação funcionando;  
* Componentização adequada;  
* Uso correto de props;  
* Organização de código;  
* Interface adequada.

**5.5. Impacto Gerado**

* Houve aplicação prática?  
* O público testou?  
* O grupo conseguiu medir algum resultado?

**5.6. Apresentação e Organização**

* Clareza na explicação;  
* Domínio do projeto;  
* Organização do documento.

**6\. MOTIVOS PARA NÃO ACEITAÇÃO DO PROJETO**  
O projeto poderá ser recusado caso:

1. Não exista validação real;  
2. Seja apenas um app genérico sem impacto social;  
3. Não utilize React Native adequadamente;  
4. Seja cópia de outro projeto;  
5. Uso indevido de IA;  
6. Não esteja alinhado com os princípios extensionistas.

**7\. OBJETIVO FINAL DA DISCIPLINA**  
Mais do que entregar um aplicativo, o objetivo é que o grupo consiga:

* Aplicar conhecimento técnico em um cenário real;  
* Trabalhar em equipe;  
* Resolver um problema concreto;  
* Desenvolver pensamento crítico;  
* Gerar impacto social através da tecnologia.
